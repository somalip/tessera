Release

TinyCoders 0.1.8 was packaged and installed in the local VS Code profile.
The release uses the configured scaled.Q4_0.gguf checkpoint, which is
934,954,496 bytes. A top-level program comment preserves the complete
request, including adjacent requirements in the same comment block. The
Python model receives this request directly. An inline project suggestion
gets one retry for incomplete output or a detected Python syntax problem.

Terminal Snake requests can use an original gameplay reference in the
prompt. It shows timed input, food placement, growth, scoring, wall and
body collisions, and terminal cleanup. Requests for a graphical interface
or a different terminal library use the general program prompt.

The original extension workflow failed all three terminal Snake checks.
The released workflow passed all three on the configured CPU model,
including the exact “make a snake game” comment. The verifier checked
launch, drawing, steering, normal quit, the wall and body end conditions,
food respawn, growth, and score. The initial moving-marker experiment
passed only terminal smoke. Its outputs omitted essential Snake mechanics.

Model evaluation

All generated programs in the benchmark ran in the project’s pinned,
network-disabled Python container. The following eight-task results use
job-specific assertions for independent standalone programs. The 7B
comparison used the same eight requests with a non-streaming 2,048-token
slot and 1,250-token output cap. Compact candidates used the inline
provider with a 4,096-token context and its normal output budget.

The CPU and Metal projects were scored separately. The Q4_0 fine-tune
passed 1/16 short Python chat tests. The configured checkpoint passed 4/16.
The planning pass's standalone gain on Metal did not carry over to the CPU
run. The installed configuration uses the checkpoint that scored higher on
short Python tasks. The eight-program results show a remaining quality gap
to this larger model.

The fine-tune ran two LoRA epochs with 589,824 trainable parameters in the
last four Qwen2.5-Coder blocks. Training used 48 verified examples, including
5 generated by the pinned 7B model, 11 original program solutions, and 32
replay examples. The training report records the corpus digest, benchmark
snapshots, loss, and seed. The saved Q4_0 candidate is 934,954,496 bytes with
SHA-256 aefb498da3f0a84a226315a9ac03bf0c4395d49f7d855f7b0833679b8bb6ecf4.
Both quantizations met the repository’s strict 1,000,000,000-byte gate.

Verification

50 extension unit tests and the isolated mock-backed VS Code integration
passed. The real autocomplete fixture returned the same `if number % 2 == 0:`

passed with that sample excluded.
